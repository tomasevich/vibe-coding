## Правила разработки

### Стандарты кода

- Используем `TypeScript` строгую типизацию
- Именование: `camelCase` для переменных, `PascalCase` для компонентов

### Стилизация

- **CSS Modules**: Используйте `*.module.css` для автоматической изоляции стилей, чтобы избежать конфликтов имен
- **CSS-in-JS (Styled Components)**: Компонентный подход — стилизуйте компоненты, а не элементы, для чистого разделения логики и оформления
- **Избегайте inline-стилей**: Используйте только для динамических значений (например, `color: props.color`)
- **Переменные**: Применяйте CSS-переменные для тем и переиспользуемых значений

### Архитектура

- App Router (NextJS 16)
- Server Components по умолчанию

> Например:
>

2. Внести изменения в код
3. Внести изменения в документацию
4. Произвести коммит в git

---

## Коммиты Git

- Формат коммитов: `type(scope): description`
- type: feat, fix, docs, style, refactor, test, chore
- scope: (component|service|utils|etc)
- description: описание изменения на английском языке в нижнем регистре
